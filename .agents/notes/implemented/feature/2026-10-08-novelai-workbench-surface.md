# Agent Note: NovelAI workbench surface (interactive studio, tag autocomplete, history canvas, quick tags, character prompts)

Status: implemented

English | [中文](2026-10-08-novelai-workbench-surface.zh.md)

## Problem

The fork targets a direct-NovelAI agent, but the only generation surface was the model tool: a user could not compose a prompt interactively, pick parameters, browse what was generated, or reuse a past generation. The desktop reference (Langbai NovelAI Studio) owns all of these interactions, and the fork's rule is to mirror them.

## Decision

The workbench is one feature package, `@deepseek-ai/dsh-client-ui-novelai-workbench`, registered into the layout's `'workbench'` slot. The sidebar carries a 对话/创作台 mode switch backed by `LayoutState.viewMode`; the frame keeps both center panes mounted and hides one, so generation state survives switching. The host side is the `NovelaiController` Remote namespace (`novelai`): `catalog`, `estimate`, `generate`, `history`, `removeEntry`, `suggestTags`, `readEntry`, `tagIndexStatus`, `downloadTagIndex`, and `splitCharacters`.

**Inject declaration.** A client plugin calling a generated Remote namespace must declare the aggregate *and* the dot-path namespace — `inject = ['remote', 'remote.novelai']` — matching the ui-conversation (`remote.session`) and ui-commands (`remote.commands`) precedent. Declaring only the dot-path fails `ctx.remote` access; declaring only the aggregate fails the namespace property. This cost the series its first live-debug round and is the convention every future remote consumer must follow.

**Parameter panel (desktop parity).** Resolution uses the desktop's model: five pixel tiers (0.4/1/1.5/2/3 MP, the 0.4 tier pinned to 409 600 px) × thirteen aspect ratios, resolved by a 64 px lattice search that scores ratio error against area usage under the official 3 Mi-pixel cap; manual width/height commit on blur or Enter, snapped to 64 px and clamped to the largest partner side. Seed is a two-segment 🎲 random / 🔒 fixed switch; fixed shows a value field plus a dice randomize button, and the completed generation's actual seed is displayed afterwards. The Anlas quote is fetched live (350 ms debounce) over width/height/steps. The negative prompt is a controlled fold.

**Structured character prompts (desktop parity).** V4+ checkpoints serialize per-character captions into the wire body: `v4_prompt.caption.char_captions` and, when at least one character carries a negative, `v4_negative_prompt.caption.char_captions`; `use_coords` is written at the top level and inside both objects, `use_order` is always `true`, and every caption carries one center — model-chosen placement uses the (0.5, 0.5) sentinel because the API fails with HTTP 500 on an empty `centers` array. Capacity is capped per checkpoint (6 for V4/V4.5, 32 for V5, 0 for V3, which hides the panel section). Coordinates clamp to the 0–1 image space. When the API rejects the structured body with HTTP 400/422 — a pre-charge validation stage — the controller folds the captions into one pipe-joined prompt (`base | char1 | char2`) and retries exactly once. Recorded entries keep their characters; backfill and one-click variation restore them.

**AI character split.** The 一键拆分 button sits beside the main prompt (outside the character fold, since it operates on the merged prompt) and sends it to the new `splitCharacters` verb, which runs one auxiliary LLM call (Config `splitProvider`/`splitModel`/`splitMaxTokens`, defaulting to the agent's own route at a 4096-token budget) with a strict-JSON instruction: character-scoped tags become per-character entries, global scene/composition/quality tags stay in the base prompt, and the answer is parsed tolerantly (prose around the JSON is ignored, a token-truncated answer is salvaged back to its last complete character entry, and an unusable answer maps to the `novelai/split-failed` namespace error — a `max-tokens` finish with parseable JSON still succeeds, and a truncated one reports the configured budget). On success the panel replaces its prompt with the returned base text and fills one card per character; the split result stays UI-local and is only ever sent onward as part of an explicit generation. Character cards give each role a tall positive caption (110 px, resizable), a per-character negative, and placement as a 自定义站位 checkbox exposing X/Y as percentages of the image space.

**Tag autocomplete.** Typing in either prompt textarea extracts the word at the caret (CJK included), debounces 80 ms with a monotonic request id so a stale response never overwrites a newer batch, and queries `suggestTags`: the local bilingual Danbooru index first (see below), then the NovelAI `suggest-tags` endpoint (Bearer token, 5 s timeout, proxy dispatch), falling back to a built-in dictionary (~134 curated entries ported from the MIT desktop app), ranked exact > prefix > substring, then post count. The dropdown anchors vertically below the caret via the mirror-div probe, offers at most 8 items, navigates with arrows, accepts with Enter/Tab, closes with Escape, and stays silent during IME composition.

**Bilingual tag index.** Full-coverage suggestions (game and anime characters such as `topaz (honkai: star rail)`) come from the desktop's optional dataset: the pinned-commit `tags_enhanced.csv` (GBK, GPL-3.0), downloaded on demand (20 MB cap, record floor, atomic replace) to the controller's `tagIndexPath` and never bundled. The first `suggestTags` call on a fresh deployment starts the download in the background; the controller also exposes `tagIndexStatus` and `downloadTagIndex`.

**History canvas (stage layout).** `readEntry` returns the PNG base64 over the JSON remote channel; the client mints object URLs, caches them per mount, and revokes them at unmount. The surface is a two-pane studio: the dominant stage shows the newest entry contain-fit, overlays a running status while a generation is in flight, and exposes a seed-reuse chip in its meta row; a horizontal filmstrip of history thumbnails swaps the stage selection (undefined selection follows the newest row, and the panel's own generations reset the selection so the fresh result lands on the stage). Clicking the stage image opens the full-screen lightbox (`role="dialog"`, `aria-modal`) with entry metadata, a parameter backfill button (fills prompt/negative/model/size/steps and switches seed to fixed), and a one-click variation (entry parameters with a fresh random seed). Below 960 px the panes stack: stage on top, control column scrolling under it.

**Quick tags and styles.** The inspiration-capsule library (curated builtin batch + three authored batches, packed `en=zh|…` strings parsed at load, merged by category/subgroup with per-category English dedup) drives a fold-open browser: category tabs, a bilingual filter, and chips that append `tag, ` to the prompt. The style presets row derives from the taxonomy's 风格画风 category and prepends the style tag.

**Enhance (desktop parity).** The stage meta row carries an Enhance action opening an inline panel: a 1–10 magnitude knob mapping to the desktop's conservative strength curve (`min(0.48, 0.10 + m×0.034)` — higher values behave like a redraw), a 1×/2× output scale whose target snaps to the 64-px lattice and reports the pixel-ceiling verdict instead of silently shrinking, and a run that resizes the stage image to the exact target pixels in a browser canvas (`enhance-image.ts`) before submission. The new `enhance` Remote verb (`runEnhancement`) resolves the workbench parameters, attaches the base64 source, and submits one img2img body — `action: "img2img"` with `parameters.image`, the clamped `strength`, the official client's fixed `noise: 0`, and a fresh `extra_noise_seed` — then settles into the library exactly like a generation. The controller's token resolution now goes through the credential seam (`NOVELAI_TOKEN` credential, then environment), so a token saved from the settings row reaches workbench generations without a restart.

**Conversation and workbench interop.** The two surfaces exchange drafts through two directed channels. Workbench → conversation: a 放入对话输入栏 button beside the prompt serializes the current draft (prompt, negative, parameters line, per-character lines) into one human-readable text and seeds it into the conversation's composer input through `conversation.seedDraft(sessionId, text)` — the InputHub's id-addressed path over the resident editor's documented programmatic `setDraft` write. Nothing is queued or sent (the user sends from the chat), the workbench prompt stays intact, and an unbound session reports `false` back to the panel as an inline error. Conversation → workbench: the `novelai_generate` tool card (ui-novelai) gains a 回填到创作台 button for settled successful calls; it extracts the request parameters from the call's durable arguments plus the actual seed from the result text and delivers them through the `novelaiWorkbench` Cordis service provided by the workbench package. Delivery without a mounted panel reports `false`; a delivered request overwrites only the present fields, clears character cards (tool calls have none), pins the seed to fixed, and switches the frame to the workbench. Both channels cross packages only through injected services and plain data — the workbench owns the bridge type, and ui-novelai consumes it `import type` plus the injected callback.

## Alternatives considered

**Serving library images through a static webserver route.** Rejected: it would add a file-serving surface for one consumer. Base64 over the existing Remote namespace keeps the trust boundary unchanged and costs a few hundred milliseconds per thumbnail on localhost.

**Bundling the Danbooru Chinese tag CSV.** Rejected as *bundled data*: the dataset is GPL-3.0 while this repo's ported data is MIT-scoped. What shipped instead is the desktop's optional download — fetched on demand into the configured path, validated (header shape, record floor, byte cap), and never committed to the repo — so full character coverage arrives without changing the license surface.

**Writing workbench generations into the conversation session.** Deferred: model-visible input requires a session event, and pushing UI-initiated images into the active session needs a session-write seam design. Generations already interoperate through the shared output library that both the workbench and the `novelai_generate` tool record into; the explicit push remains open work.

**Persistent user-created style presets.** Deferred: the desktop stores them in app data with an image manager. The fork ships curated presets derived from the capsule taxonomy; user-authored presets would want a settings-namespace contribution and arrive with it.

## Consequences

`packages/client/ui-novelai-workbench` (panel, autocomplete, capsule, history, character cards, draft composition, backfill bridge), `packages/client/ui-novelai` (tool card, turn-tail images, card backfill button), `packages/api/novelai-controller` (namespace verbs, dictionary, scoring, character-split LLM call), and `packages/novelai/novelai-core` (`requestTagSuggestions`, structured character payload serialization) grew; the api-remotes client bundle embeds the regenerated namespace and must be rebuilt after any controller verb change — a stale remotes bundle manifests as a silently swallowed property-proxy miss, so verb additions are not complete until that bundle is rebuilt and the page reloaded. Component specs cover the panel, autocomplete, capsule, history, character-card, draft-send/backfill, and tool-card backfill behaviors; host specs cover dictionary ranking, split-answer parsing, and the pipe fallback. Known deferred work: the session-push interop above, persistent style presets, and a draggable position canvas (cards expose numeric X/Y today).
