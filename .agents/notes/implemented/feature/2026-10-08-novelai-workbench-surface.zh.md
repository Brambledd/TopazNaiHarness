# Agent Note：NovelAI 创作台（互动画板、tag 联想、历史画布、快捷标签、角色提示词）

状态：已实现

[English](2026-10-08-novelai-workbench-surface.md) | 中文

## 问题

本 fork 的目标是直连 NovelAI 的 agent，但此前唯一的生成入口是模型工具：用户无法交互式地写提示词、挑参数、浏览生成结果，也无法复用历史生成。桌面参考实现（Langbai NovelAI Studio）拥有这套交互，而本 fork 的规则是照搬它。

## 决定

创作台是一个功能包 `@deepseek-ai/dsh-client-ui-novelai-workbench`，注册进 layout 的 `'workbench'` 槽位。侧栏带 对话/创作台 模式开关，底层是 `LayoutState.viewMode`；AppFrame 让两个中栏常驻、只隐藏一个，因此切换时生成状态不丢。宿主侧是 `NovelaiController` 的 Remote 命名空间（`novelai`）：`catalog`、`estimate`、`generate`、`history`、`removeEntry`、`suggestTags`、`readEntry`、`tagIndexStatus`、`downloadTagIndex`、`splitCharacters`。

**注入声明。** 客户端插件调用生成的 Remote 命名空间时必须同时声明聚合与点路径命名空间——`inject = ['remote', 'remote.novelai']`——与 ui-conversation（`remote.session`）、ui-commands（`remote.commands`）的先例一致。只声明点路径会让 `ctx.remote` 取不到；只声明聚合会让命名空间属性取不到。本系列第一轮在线调试就栽在这里，后续所有 remote 消费方都必须沿用这个约定。

**参数面板（桌面同款）。** 分辨率沿用桌面模型：五档像素（0.4/1/1.5/2/3 MP，0.4 档固定 409 600 px）× 十三个画面比例，由 64px 格点搜索求解——在官方 3Mi 像素上限下按「比例误差 + 面积利用」打分；手动宽高在失焦或回车时提交，对齐 64px 并夹到配对边的最大合法值。种子是 🎲随机/🔒固定 两段开关；固定档展示数值框和骰子随机按钮，生成完成后展示实际使用的种子。Anlas 报价随宽高步数实时刷新（350ms 防抖）。负面提示词是受控折叠。

**结构化角色提示词（桌面同款）。** V4+ 模型把每个角色的描述序列化进线格式：`v4_prompt.caption.char_captions`，以及——仅当至少一个角色填了负面时——`v4_negative_prompt.caption.char_captions`；`use_coords` 同时写在顶层与两个结构体内部，`use_order` 恒为 `true`，每条描述必须带一个中心点——AI 自选站位用 (0.5, 0.5) 哨兵值，因为 `centers` 为空时 API 直接 HTTP 500。容量按模型封顶（V4/V4.5 为 6，V5 为 32，V3 为 0 并隐藏面板分区）。坐标夹到 0–1 图像空间。当 API 以 HTTP 400/422 拒绝结构化请求体——这是扣费前的校验阶段——控制器把各角色描述折叠成竖线拼接（`主提示词 | 角色1 | 角色2`）并恰好重试一次。完成的条目会记录角色数据；回填与一键变体会还原它们。

**AI 角色拆分。** 「一键拆分」按钮常驻在主提示词旁（折叠区之外——它作用于合并提示词），把提示词发给新的 `splitCharacters` 动词，后者执行一次辅助 LLM 调用（Config `splitProvider`/`splitModel`/`splitMaxTokens`，默认沿用 agent 自身的路由，输出预算 4096 token），指令要求严格 JSON：角色限定标签拆成逐角色条目，全局的场景/构图/画质标签留在主提示词，答案做宽容解析（JSON 前后的说明文字被忽略；撞到 token 上限的答案会抢救回最后一个完整角色条目；不可用答案映射为 `novelai/split-failed` 命名空间错误——`max-tokens` 结束但 JSON 完整仍算成功，真被截断时报错并提示配置的预算值）。成功后面板把主提示词替换为返回的基础文案，并为每个角色填一张卡片；拆分结果只留在 UI，仅随用户显式发起的生成再外发。角色卡片给每个角色 110px 可拉伸的正向描述框、独立负面框，站位是「自定义站位」复选框，展开后以图像空间百分比编辑 X/Y。

**Tag 联想。** 两个提示词输入框打字时提取光标处单词（含中文），80ms 防抖并携带单调递增的请求号——迟到的旧响应不会覆盖更新一批结果——然后查询 `suggestTags`：先查本地双语 Danbooru 索引（见下），再走 NovelAI `suggest-tags` 端点（Bearer、5s 超时、走代理），失败或为空时回退到内置词典（约 134 条策展词条，移植自 MIT 的桌面版），排序为 精确 > 前缀 > 包含，同分按热度。下拉经镜像 div 探测锚定在光标行下方，最多 8 条，方向键导航、Enter/Tab 采纳、Escape 关闭，输入法组字期间保持静默。

**双语标签索引。** 全量联想（`topaz (honkai: star rail)` 一类游戏与动漫角色）来自桌面版的可选数据集：固定 commit 的 `tags_enhanced.csv`（GBK、GPL-3.0），按需下载（20MB 上限、记录数下限、原子替换）到控制器的 `tagIndexPath`，永不进仓库。新部署的第一次 `suggestTags` 会在后台启动下载；控制器同时暴露 `tagIndexStatus` 与 `downloadTagIndex`。

**历史画布（舞台结构）。** `readEntry` 经 JSON remote 通道返回 PNG base64；客户端铸造 object URL、按挂载缓存、卸载时统一撤销。界面为双栏工作室：占主导的舞台以 contain 适配展示最新条目，生成进行中覆盖运行状态遮罩，元信息行提供种子复用芯片；历史缩略图胶片带横向排列，单击切换舞台选择（未选择时跟随最新行，面板自身的生成会重置选择，让新结果落上舞台）。点击舞台图打开全屏灯箱（`role="dialog"`、`aria-modal`），带条目元数据、「回填参数」按钮（填入提示词/负面/模型/尺寸/步数并把种子切到固定）与一键「变体」（沿用条目参数换新随机种子）。960 px 以下双栏改为上下堆叠：舞台在上，控制列在下滚动。

**快捷标签与风格库。** 灵感胶囊库（策展内置批 + 三个自著批，压缩 `en=zh|…` 串加载时解析，按类别/子组合并、类别内按英文去重）驱动折叠式浏览器：类别页签、双语过滤、点击即向提示词追加 `tag, `。风格库一行派生自分类法的「风格画风」类，点击把风格 tag 前置到提示词。

**对话与创作台互通。** 两个界面通过两条定向通道交换草稿。创作台 → 对话：主提示词旁的「发送到对话」按钮把当前草稿（提示词、负面、参数行、逐角色行）序列化成一段可读文本，经 `sessions.scope(id).session.prompt(..., 'queue')` 作为一条真实用户消息进入当前对话排队——不需要新事件类型，模型可见输入本身就是已落盘的 `user/message`。成功后面板切到对话视图。对话 → 创作台：`novelai_generate` 工具卡（ui-novelai）在调用成功落定后显示「回填到创作台」按钮，从调用的持久化参数里抽取请求字段、从结果文本解析实际种子，经创作台包提供的 `novelaiWorkbench` Cordis 服务投递。面板未挂载时投递返回 `false`；已投递的请求只覆盖出现的字段、清空角色卡片（工具调用没有角色）、把种子切到固定档，并把界面切到创作台。两条通道都只经注入服务与纯数据跨包——桥类型归创作台包所有，ui-novelai 以 `import type` 加注入回调消费。

## 备选方案

**用静态文件路由对外提供图库图片。** 否决：为单一消费方新增一个文件服务面。走既有 Remote 通道传 base64 不改变信任边界，本地回环下每张缩略图只多几百毫秒。

**内置 Danbooru 中文 CSV 索引。** 作为*内置数据*是否决的：数据集为 GPL-3.0，而本仓库移植的数据保持 MIT 边界。实际落地的是桌面版的可选下载——按需拉取到配置路径，校验（表头形状、记录数下限、字节上限），永不提交进仓库——在不改变许可证面的前提下拿到全量角色覆盖。

**把创作台生成写进对话会话。** 暂缓：模型可见输入必须有会话事件，把 UI 发起的图片推进当前会话需要先设计会话写入缝隙。生成已通过共享输出目录互通（创作台与 `novelai_generate` 工具写同一库）；显式推送留作后续工作。

**用户自建风格预设的持久化。** 暂缓：桌面版存于应用数据目录并带图片管理器。本 fork 先提供从胶囊分类法派生的策展预设；用户自建预设需要 settings 命名空间扩展，届时一并落地。

## 后果

`packages/client/ui-novelai-workbench`（面板、联想、胶囊、历史、角色卡片、草稿发送、回填桥）、`packages/client/ui-novelai`（工具卡、回合尾图、卡片回填按钮）、`packages/api/novelai-controller`（命名空间动词、词典、评分、角色拆分 LLM 调用）与 `packages/novelai/novelai-core`（`requestTagSuggestions`、结构化角色载荷序列化）扩展；api-remotes 的客户端 bundle 内嵌再生成的命名空间，控制器动词变更后必须重建该 bundle——陈旧的 remotes bundle 表现为属性代理静默失配，因此动词新增在重建 bundle 并刷新页面前不算完成。组件 spec 覆盖面板、联想、胶囊、历史、角色卡片、草稿发送/回填与工具卡回填行为；宿主 spec 覆盖词典评分、拆分答案解析与竖线回退。已知暂缓项：上述会话推送互通、风格预设持久化，以及可拖拽站位画布（当前卡片以数值 X/Y 输入）。
