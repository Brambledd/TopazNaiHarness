# Agent Note: 提示词补丁的角色槽（对话侧结构化多人物编辑）

状态：已实现

[English](2026-10-14-novelai-patch-characters-slot.md) | 中文

## 问题

`novelai_prompt_patch` 只能作用于正向、负向和参数三个槽。操作者请求多人物场景时，模型忠实地遵循工具「先补丁、再生成」的契约——却除了正向槽无处安放角色。一份会话日志显示 22 条正向槽操作把每个角色的特征全部混进共享提示词；创作台面板保持零角色卡，生成跑在旧的混合提示词上。`novelai_generate` 的结构化 `characters` 参数和它的回填分卡全程没有登场，因为面板上没有可供回填的角色。

## 决策

补丁词汇表长出第四个槽——`characters`——整条链路都会说它：

- **工具侧（`tool-novelai`）**——schema 接受每操作一个 1 基整数 `character`；`normalizePatch` 拒绝缺失、为零、小数或缺标签的角色操作，并在纯字符串记录的结果里把 `character` 输出为字符串（无损 JSON 结果边界）。`PATCH_DESCRIPTION` 现在以多人物规则开头：每个角色拥有自己的操作与编号，只有共享场景标签（场景、光照、构图、质量）才属于正向槽。
- **卡片侧（`ui-novelai`）**——槽位标签映射新增 `patch.slot.characters`，每条操作渲染 `角色 {n}` / `character {n}` 前缀，操作者在应用前就能看清每行编辑哪张卡。
- **面板侧（`ui-novelai-workbench`）**——`applyPatchRequest` 的角色分支物化直到最大引用编号的卡片（按模型容量截断），用与正向槽相同的加/删/改语义编辑各卡提示词标签，并展开折叠栏让卡片落位可见。共享提示词完全不被触碰。
- **新鲜闭包订阅**——补丁订阅 effect 去掉了依赖数组：订阅者必须是当前渲染的闭包，因为角色分支读取 `model` 计算容量，陈旧的首渲染闭包会把每个补丁钳到未播种容量 0。旧的依赖数组正是带着这个缺陷发布的；正向/负向/参数分支从不读状态，所以只有新分支暴露了它。
- **补丁卡片的提案权限不变**——补丁仍然只提议并等待操作者的应用；`novelai_generate` 继续读取已提交的面板状态，生成的请求如今直接带着角色卡里结构化的 `characters`。

## 后果

- 多人物请求现在以各自独立的角色卡收尾，每张卡在自己的提示词块下生成，而不是一团混合的正向提示词。
- 陈旧闭包隐患对所有未来的补丁分支一并修复：`applyPatchRequest` 内的任何状态读取都安全，因为订阅每渲染重订。
- 角色级负面提示词与坐标仍由面板手动管理；补丁槽只编辑提示词（schema 不携带 `x`/`y`），保持操作记录在无损 JSON 边界两侧都是字符串映射。
